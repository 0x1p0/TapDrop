# TapDrop website

The site for TapDrop: a static Astro site with GSAP and Lenis for motion, in the apps' Lumen design (Instrument Serif,
Geist, night and bone, one cool light). The app images are real captures from the Mac and Android apps; the receipt and
the fingerprint grids in "Never a screenshot" are generated by `scripts/originals.mjs`. TapDrop is free and open source
under the MIT License.

## Run it in development

```sh
cd site
npm install
npm run dev          # http://localhost:4321
```

Node 22 or newer. The dev server hot-reloads, but judge motion and speed on a production build.

When the install steps change, update `docs/INSTALL.md` first, then `src/pages/get-started.astro` to match.

## Build and preview for production

```sh
cd site
npm run build        # writes the static site to site/dist
npm run preview      # serves dist on http://localhost:4321
```

`dist/` is plain static files (HTML, CSS, JS, images, the film).

## Deploy

The site is the `tapdrop` project on Cloudflare Pages, at https://tapdrop.pages.dev. Every push to `main` that
changes `site/` deploys it (`.github/workflows/website.yml`, with the `CLOUDFLARE_API_TOKEN` and
`CLOUDFLARE_ACCOUNT_ID` secrets). To deploy by hand, logged in with `npx wrangler login`:

```sh
npm run deploy       # builds, then uploads dist to the tapdrop project
```

The address lives in `site` in `astro.config.mjs`, `url` in `src/data/site.ts` (canonical links, Open Graph tags and
the sitemap) and the `Sitemap:` line in `public/robots.txt`.

## Where things live

| Path | What it is |
|---|---|
| `src/data/site.ts` | Every line of copy on the home page, the requirements and the setup steps |
| `src/pages/` | `index.astro` (home), `how-it-works.astro`, `get-started.astro` (the install guide, from `docs/INSTALL.md`), `404.astro` |
| `src/components/` | The menu bar with the notch, the phone illustration, the light trace, the five-tap stage, result windows, buttons, footer, and the guide's key labels, menu paths and copyable commands |
| `src/motion/` | `hero.ts` (the tap on the home page), `tapsends.ts` (the five-tap stage), `notch.ts` (the light reading and the island), `trace.ts`, `ui.ts`, `setup.ts` (page transitions) |
| `src/engine/` | Smooth scroll, reveals and the page lifecycle, all on GSAP's single ticker |
| `src/styles/` | `tokens.css` (colors, type scale, notch size), `base.css`, `site.css`, `sends.css` |
| `src/assets/` | Real captures: `island/` (Mac notch island), `phone/` (Android screens), `mac/`, `photo/` |
| `public/media/` | The film (`tapdrop-film.mp4`, H.264, 1080p30, about 10 MB), its poster, and a 6 s muted loop of the real video for the five-tap stage |
| `DESIGN.md` | The concept, palette, type, grid and motion rules for this site |

## Updating the films

Three films live in `public/media/`, each with a poster: `tapdrop-film.mp4` + `film-poster.webp` (home),
`setup-mac.mp4` + `setup-mac-poster.webp` and `setup-android.mp4` + `setup-android-poster.webp` (the install guide).
`src/data/media.ts` resolves them at build time: a missing video shows its poster with "The film is on its way", a
missing poster falls back to the Lumen placeholder in `public/media/placeholder/`, and each film's length on its play
button is read from the MP4 itself. Encode for the web from the renders in `video/out/`, for example:

```sh
IN=../video/out/TapDrop-2.1.mp4
ffmpeg -y -i $IN -vf "fps=30,scale=1920:1080" -c:v libx264 -preset slow -crf 22 -pix_fmt yuv420p \
  -c:a aac -b:a 96k -movflags +faststart public/media/tapdrop-film.mp4
```

## The fingerprint figure

`node scripts/originals.mjs` regenerates `src/assets/originals/` (the receipt photo and still renders of the grids)
and `src/data/originals.json` (the grids and scores the page draws). Its scores are the real correlations of those
grids, tuned to a real run: rank 1 at 0.959 against 0.537, then 0.99 up close.

## Accessibility and motion

With reduced motion on, there is no smooth scroll, no scrubbed tap and no transitions beyond short fades: the tap is
laid out as a still sequence, and every section is fully visible. The site works without JavaScript too.
